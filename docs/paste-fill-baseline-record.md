## 迭代记录（粘贴填 · Select）

### 2026-04-23：产品名称（antd@4 可搜索 Select）「假填」修复与复验

- **现象（用户截图）**：表单项为 **Select（可搜索）**，框内已出现「乐通分期」等字样，但红框与「请选择」校验仍在；即 **搜索输入态 ≠ 已选中 option**，表单值仍未提交。
- **原因简述**：在仅输入搜索词阶段对 `rc-select` / antd@4 派发 **Enter** 可能提前关闭下拉；若未真正点选下拉 **menu-item** 完成提交，会出现「看起来像填了、校验仍当未选」。
- **实现改动**（`src/content/antd-adapter.ts`）：
  - **`tryTypeSelectSearch`**：只负责把搜索词写入搜索框并触发 `input`/`change`（沿用 `setNativeValue`），**不再在搜索阶段模拟 Enter**。
  - **`fillSelect`**：每次点选候选后，根据 **`.ant-select-selection-item`**（antd5）或 **`.ant-select-selection-selected-value`**（antd4）轮询校验 **真选中**：非占位文案，且与目标值匹配（`random` 模式则要求已脱离占位态）；未满足则继续等待/重试，避免早退误报成功。
  - **antd4 下拉**：优先点击 **`.ant-select-dropdown-menu-item-content`**（高亮项路径同样收敛到该目标），贴近真实用户点选。
- **自动化**：`src/__tests__/failure-cases.test.ts` 增补「antd4 可搜索 Select 必须点 menu-item 提交」等回归；工作区 **`npm test` 全绿**。
- **构建**：**`npm run build:content`** 已通过（扩展需重载或刷新后再验真实页）。
- **人工复验**：用户反馈 **「这次可以了」** — 产品名称等可搜索 Select 已能稳定点选提交，不再停留在仅搜索框有字的状态。
